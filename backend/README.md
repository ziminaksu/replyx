# ReplyX — AI Campus Copilot for TUM Students

Built at Reply Hackathon 2026.

ReplyX lets TUM students ask natural-language questions about their lecture slides and get answers grounded directly in course material — with the source slide rendered inline — instead of manually searching through Moodle. It also automates homework submission and keeps its knowledge base in sync with newly published lectures.

## Features

- **RAG-based slide Q&A** — ask a question in plain language and get an answer generated from the actual lecture content, with the relevant slide rendered as an image alongside the response.
- **Semantic slide search** — HNSW-indexed cosine similarity search over embedded slide text (ChromaDB, Qwen3-Embedding-0.6B).
- **Direct slide lookup** — ask for a specific slide or page number (e.g. "show me slide 12 on virtualization") and get it directly, with a semantic fallback if the exact slide isn't found.
- **Homework submission agent** — upload a homework file with group/member info; the agent processes it and compiles a final submission PDF.
- **Autonomous Moodle sync agent** — a scheduled agent logs into TUM Moodle via Shibboleth SSO, detects newly published lecture PDFs, downloads them, and re-indexes the vector database automatically.
- **LLM-backed answers** — responses are generated by Claude (Sonnet) via AWS Bedrock, grounded in retrieved slide content.

## Architecture

```
replyx/
├── backend/
│   ├── main.py          # FastAPI app — search, RAG Q&A, slide image rendering,
│   │                     # homework submit/download, Moodle sync endpoints
│   ├── hw_agent.py       # homework processing agent
│   ├── moodle_sync.py    # autonomous agent that watches for new lecture PDFs
│   ├── embeddings.py     # ChromaDB vector store setup & semantic search
│   ├── slides.py         # slide PDF processing / indexing
│   └── requirements.txt
├── tum_assistant/        # Q&A assistant module
├── notebooks/            # experimentation / prototyping
├── data/                 # slides, uploads, processed data
├── chroma_db/            # local vector database
├── slide_search.py       # standalone slide indexing/search prototype (Qdrant + HNSW)
├── run.py                # unified launcher — starts the backend, serves the frontend, opens the browser
└── README.md
```

**Backend (`backend/main.py`)** exposes a FastAPI app with endpoints for semantic search, RAG-based Q&A (with slide-number detection and image rendering), homework submission/download, and Moodle sync status/trigger.

**Retrieval** is handled through ChromaDB with an HNSW cosine-similarity index, using sentence-transformer embeddings (Qwen3-Embedding-0.6B) over slide text extracted with PyMuPDF.

**Answer generation** calls Claude Sonnet through AWS Bedrock, with prompts that ground responses in retrieved slide content and reference the source PDF/slide number.

**Moodle sync agent (`backend/moodle_sync.py`)** runs on a schedule, checks for newly published lecture PDFs, and triggers re-indexing when new content is found — keeping the knowledge base current without manual uploads.

## Tech stack

Python · FastAPI · ChromaDB · Qdrant · sentence-transformers · PyMuPDF · AWS Bedrock (Claude) · boto3 · schedule

## Getting started

```bash
pip install -r backend/requirements.txt
python run.py
```

`run.py` starts the FastAPI backend, mounts the frontend, and opens it in your browser. AWS credentials for Bedrock access and a Gemini API key (in `tum_assistant/.env`) are required for the Q&A features.
